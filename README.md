# 東京23区 中古マンション価格予測 — ベースライン

2026/06/05 進捗会議の議論を踏まえ、リポジトリを刷新したベースライン。
区ごとの個別モデルから「23区プール＋サブグループ」へ、単年R²から「分布での評価」へ作り直している。

## パイプライン

```
01_load_data.py       サイトからDLしたCSV(日本語列)を読み込み・英語スキーマに統一
02_features.py        特徴量作成＋決定論的クレンジングのみ（統計的トリミングはしない）
03_temporal_lag.py    町丁目×年の時間ラグ Lag1/2/3
04_spatial_features.py 重心座標・空間ラグ(23区一括の隣接)
05_baseline_models.py プール OLS / XGBoost を Expanding Window で複数年評価
06_report.py          R²を分布(平均±標準偏差)として可視化
07_transformer_compare.py Transformer(FT-Transformer簡易版) vs XGB を同一プロトコルで比較
08_ablation.py        特徴量アブレーション（前進ネスト＋leave-one-out）。立地系特徴量の追加寄与を検証
```

実行は番号順。`config.py` でパス・特徴量・IQR設定・空間重みを一元管理している。

## 議事録アクションアイテムとの対応

| 議事録の指摘 | この実装での対応 |
|---|---|
| R²=0.7 は特定年にたまたま当たった可能性 | `05` で 2010-2023 を順に検証年にした Expanding Window。`06` は単年でなく平均±標準偏差で報告 |
| 23区全体でプールして分析（Kobayashi） | `05` は区ごとループを廃止し、Municipality を one-hot＋重心座標で表現した単一モデルを学習 |
| 都心5区とその他を分けて分析 | `config.CENTRAL_5` でサブグループを定義し、予測の事後スライスでR²を比較 |
| 空間ラグが行政区隣接で粗い | `04`＋`src/lib_spatial.py` で 23区を一括処理。区境の町も隣区の近隣を取得。`SPATIAL_WEIGHT="knn"` で行政界非依存の近傍も選択可 |
| IQR処理は慎重に・論文で明示 | クレンジング(02)と統計的トリミング(05)を分離。トリミング閾値は訓練フォールドの分布のみから決定（リーク防止）。係数 `IQR_K` は config に明記 |
| 駅距離を特徴量に | サイト版CSVの「最寄駅：距離（分）」を物件単位で数値化し `Station_min` として投入。APIでは取れなかった駅情報をDL版で補完。範囲表記(30分～60分 等)も代表値に変換 |
| 重心座標を特徴量に | `lib_spatial.add_centroids`（投影座標系 EPSG:6677、町単位） |
| 受付帳データの活用 | スキーマ未確定。`02` の後に町丁目キーで left-join する差し込み口を想定（要データ仕様確認） |
| Transformer は比較対象の一つ | `07`＋`src/lib_transformer.py`。FT-Transformer簡易版を sklearn互換I/Fで実装し、XGBと同一の特徴量・Expanding Window・IQR運用で比較 |
| テスト側トリミングの感度分析 | 全結果に `r2`(素・主指標) と `r2_trim`(訓練フォールド由来のIQR閾値をテストにも適用) を併記。閾値はテスト分布を見ないのでリークなし |

## 必要データ（各自で配置）

- `data/raw/Tokyo_20053_20254.csv` … 不動産情報ライブラリのサイトからDLしたCSV（中古マンション・東京、Shift_JIS）。**駅情報を含むのでこれを正本にする**
- `data/shape/r2ka13.shp` … 令和2年 国勢調査 東京都 町丁目（重心とS-lagの隣接計算に必要）

APIキーや駅shapefile(N02)はもう不要。駅距離はCSVの「最寄駅：距離（分）」を使う。

## 特徴量アブレーションの知見（08）

全16フォルドのleave-one-out（フルから1特徴量を抜いたR²低下）:

| 抜いた特徴量 | ΔR²(ALL) | 解釈 |
|---|---|---|
| Lag（町の過去価格） | −0.131 | 圧倒的に支配的 |
| Station_min（駅まで時間） | −0.009 | **非Lagで最大の寄与。残る** |
| Station_TE（駅名identity） | −0.004 | ほぼ冗長 |
| Zoning（用途地域） | −0.000 | 冗長 |

駅名・区・用途地域は町の中で一定なので町レベルのLagに吸収されるが、Station_minは
同一町内でも物件ごとに異なるためLagが捉えない町内変動を持ち、追加寄与が残る。
→ 立地のカテゴリ系特徴量の追加は打ち切り、Station_min(連続)は維持。次の上積みは
価格ラグに吸収されない情報（受付帳の取引量）に求める。
